# 麦门汇率局 · mcd-points-fx

> 你的麦麦积分不是「分」，是一种会过期、有汇率、还能被悄悄稀释的货币。
> 这个 Skill 把它的真实汇率算清楚，并告诉你过期前该怎么花。

麦当劳 MCP 的 35 个工具里，有 4 个能凑出一个别人没做过的东西：
**把积分当货币做汇率分析。**

---

## 核心发现

把积分商城当前全部可兑换商品换算成「元/积分」后，规律很干净：

| 积分档位 | 商品数 | 平均汇率 |
|---:|---:|---:|
| 50 分 | 4 | **0.1925 元/分** |
| 100 分 | 3 | 0.1617 元/分 |
| 200 分 | 3 | 0.0777 元/分 |
| 500 分 | 6 | 0.0427 元/分 |
| 800 分 | 3 | **0.0332 元/分** |

**单调递减，50 分档 → 800 分档跌了 83%，差 5.8 倍。**

同样是 18.8 元的东西：

- 50 分就能换「麦辣鸡腿汉堡两件套」
- 但 800 分换「板烧四件套」也只有 28.9 元

也就是说，**面额越大的商品，每 1 积分买到的钱越少**。
而积分商城按类目排序、不按汇率排序——用户靠肉眼永远发现不了这件事。

> 数据取自 2026-10-24 的实时接口快照，商品池变动后数值会变，结论方向不变。

## 它还能算出什么

- **我的积分值多少钱**：已过期积分按小额档汇率折算，是多少钱蒸发掉了
- **过期前怎么花最优**：0/1 背包求最优兑换组合，不是拍脑袋推荐
- **闭眼换会亏多少**：同预算下的最差组合做对照，差额才是决策依据
- **该去哪家店**：积分商品多为「到店专用」，给出最近门店与营业时间

## 目标用户

- 有麦麦积分但从来不知道能换什么、换得值不值的人
- 积分快过期才开始着急的人（余额里有一笔「有截止日期的钱」）
- 想验证「积分商城是不是在偷偷贬值」的人

## 快速开始

### 1. 申请 MCP Token

到 [open.mcd.cn](https://open.mcd.cn/mcp) 用手机号登录 → 右上角「控制台」→ 激活 → 复制 Token。

### 2. 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，填入你的 Token
```

```ini
MCD_MCP_TOKEN=你的Token
MCD_MCP_URL=https://mcp.mcd.cn
```

> Token 只存在本地 `.env`（已被 `.gitignore` 排除），不会进仓库，也不会上传。

### 3. 跑

零第三方依赖，只需要 Python 3.10+：

```bash
python -m src.cli                              # 终端报告
python -m src.cli --html out/report.html       # 生成可分享卡片
python -m src.cli --budget 154                 # 只用即将过期的积分做预算
python -m src.cli --json out/report.json       # 导出结构化结果
```

### 4. 作为 WorkBuddy Skill 使用

把本目录放进 `~/.workbuddy/skills/`，然后直接说：

> 麦门汇率局，帮我看看我的积分怎么花最划算

Skill 会按 `SKILL.md` 的流程自动取数、算汇率、给方案。

## 输出示例

```
【资产】
  可用积分           285.5
  其中本月将过期     154.6  <- 有截止日期的钱
  已过期作废         191.6  <- ≈ ¥36.9 已经蒸发掉

【汇率衰减】积分面额越大，汇率越差
    50 分档 ( 4件)  0.1925 元/分  ███████████████████
   100 分档 ( 3件)  0.1617 元/分  ████████████████
   200 分档 ( 3件)  0.0777 元/分  ███████
   500 分档 ( 6件)  0.0427 元/分  ████
   800 分档 ( 3件)  0.0332 元/分  ███
  50分档 → 800分档 汇率掉 83%（5.8 倍差距）

【最优花法】预算 = 本月将过期 154.6 分
  · 18.8元麦辣鸡腿汉堡两件套  (50 分 / 价值 ¥18.8)
  · 18.8元板烧鸡腿堡两件套  (100 分 / 价值 ¥18.8)
  → 花掉 150 分，换回 ¥37.6，剩 4 分
  → 综合汇率 0.2507 元/分

  对照：同样 150 分，闭眼换能拿到的最差组合是
    · 10.9元指定小食任选  (100 分 / ¥10.9)
    · 5.9元香芋派/菠萝派任选  (50 分 / ¥5.9)
  → 只有 ¥16.8，差 ¥20.8（最优是最差的 2.2 倍）
```

> 示例数值来自一次真实调用，仅作演示；实际结果取决于你的账户与当日商品池。

`--html` 会生成一张自包含卡片，无外部字体/图片/CDN，断网可开，可直接截图分享。

## 技术要点

| 设计 | 原因 |
|---|---|
| 纯标准库，零第三方依赖 | clone 下来就能跑，不用装 requests/httpx |
| 兼容裸 JSON 与 SSE 两种响应 | Streamable HTTP 服务端可能返回 `text/event-stream` |
| 从 `spuName` 解析商品价值 | 积分商品的 `price` 字段几乎全是 `"0"`，真正的标价在名称里 |
| 0/1 背包而非贪心 | 贪心会留下无法利用的零头，拿不到全局最优 |
| 最差对照方案 | 没有参照系的「最优值」不产生决策价值 |
| 商品池主动过滤 | 宁可少算几个，也不让汇率表出现错误数字 |

更多细节见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。
